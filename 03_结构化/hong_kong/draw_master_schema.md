# 香港每期主数据标准

**schema_name:** hong_kong_draw_master_schema
**schema_version:** 1.0
**market:** hong_kong
**status:** active

---

## 1. 设计目的

本 Schema 用于统一保存香港每一期的原始资料、卦象资料、八肖资料、号码映射、分层分析结果及实际开奖结果。

核心原则：

> 原始资料与分析结果分离，所有分析结果必须可以追溯到原始资料。

---

## 2. 数据身份

| 字段             | 类型      | 必填 | 说明                       |
| -------------- | ------- | -: | ------------------------ |
| draw_id        | string  |  是 | 每期唯一 ID，例如 `HK-2026-092` |
| year           | integer |  是 | 年份                       |
| period         | integer |  是 | 期号                       |
| draw_date      | string  |  否 | 开奖日期                     |
| market         | string  |  是 | 固定为 `hong_kong`          |
| source         | string  |  是 | 数据来源                     |
| source_version | string  |  否 | 原始资料版本                   |

### draw_id 规则

香港：

`HK-年份-期号`

例如：

`HK-2026-092`

---

## 3. RAW 原始资料

原始资料必须完整保存。

| 字段              | 类型     | 必填 | 说明     |
| --------------- | ------ | -: | ------ |
| raw_data        | object |  是 | 本期原始资料 |
| raw_text        | string |  否 | 原始文字   |
| raw_source_file | string |  否 | 原始文件名称 |
| raw_import_time | string |  是 | 导入时间   |

### RAW 原则

1. 原始资料不得覆盖。
2. 原始资料不得因为分析结果改变而修改。
3. 原始资料如发现错误，应新增修正版并保留旧版本。
4. 原始资料必须能够追溯来源文件。

---

## 4. 香港卦象资料

目前香港数据库确定保存三套主要起卦资料：

* 21画
* 29画
* 42画

| 字段          | 类型     | 必填 | 说明      |
| ----------- | ------ | -: | ------- |
| hexagram_21 | object |  否 | 21画起卦卦象 |
| hexagram_29 | object |  否 | 29画起卦卦象 |
| hexagram_42 | object |  否 | 42画起卦卦象 |

### 卦象对象建议字段

| 字段                   | 类型      | 说明        |
| -------------------- | ------- | --------- |
| source               | string  | 起卦来源      |
| stroke               | integer | 对应笔画      |
| divination_value     | string  | 起卦数字/原始数值 |
| hexagram_name        | string  | 卦名        |
| upper_trigram        | string  | 上卦        |
| lower_trigram        | string  | 下卦        |
| moving_line          | string  | 动爻，如有     |
| changed_hexagram     | string  | 变卦，如有     |
| original_description | string  | 原始卦象描述    |
| source_file          | string  | 来源文件      |
| verified             | boolean | 是否核验      |

### 卦象保存原则

1. 21画、29画、42画必须分别保存。
2. 不得把三套卦象合并成一个无法追溯来源的字段。
3. 原始卦象与解释结果分开。
4. 不确定的卦象不得自行补造。
5. 卦象资料如需修正，保留原记录并通过版本控制追踪。

---

## 5. 八肖资料

八肖属于辅助筛选资料。

| 字段              | 类型      | 必填 | 说明         |
| --------------- | ------- | -: | ---------- |
| zodiac_8        | array   |  否 | 本期数据库提供的八肖 |
| zodiac_source   | string  |  否 | 八肖来源       |
| zodiac_verified | boolean |  否 | 是否核验       |

### 八肖原则

八肖可以参与号码筛选，但：

> 八肖 ≠ 最终号码。

八肖不能覆盖或修改原始卦象。

---

## 6. 49个固定号码与生肖映射

49个号码属于固定号码全集及生肖映射基础资料。

**49码不是分析层级。**

| 字段               | 类型     | 说明      |
| ---------------- | ------ | ------- |
| number_mapping   | object | 号码与生肖映射 |
| zodiac_numbers   | object | 各生肖对应号码 |
| mapping_version  | string | 映射规则版本  |
| excluded_numbers | array  | 明确排除号码  |

### 映射原则

生肖号码按照当前年份生肖规则使用。

号码全集固定为：

`01–49`

生肖对应关系由 `mapping_version` 控制。

立春后进入新的生肖年份时，使用新的生肖号码映射版本。

---

## 7. 候选号码

卦象分析与八肖筛选产生候选号码。

| 字段                | 类型     | 说明     |
| ----------------- | ------ | ------ |
| candidate_numbers | array  | 候选号码   |
| candidate_source  | array  | 候选来源   |
| candidate_reason  | object | 筛选原因   |
| candidate_version | string | 候选规则版本 |

候选号码必须能够追溯：

```text
卦象
 ↓
八肖
 ↓
号码映射
 ↓
候选号码
```

---

## 8. 六级分析层

正式分析层级固定为：

```text
八肖
 ↓
28码
 ↓
24码
 ↓
20码
 ↓
16码
 ↓
12码
 ↓
8码
```

### 重要规定

**49码不属于分析层级。**

49码只作为固定号码全集及生肖映射基础。

| 字段           | 类型    | 说明    |
| ------------ | ----- | ----- |
| candidate_28 | array | 28码候选 |
| candidate_24 | array | 24码候选 |
| candidate_20 | array | 20码候选 |
| candidate_16 | array | 16码候选 |
| candidate_12 | array | 12码候选 |
| candidate_8  | array | 8码候选  |

### 分层原则

每一层必须能够说明：

1. 来源于上一层哪些号码。
2. 删除了哪些号码。
3. 保留了哪些号码。
4. 使用了什么筛选规则。
5. 对应的规则版本是什么。

---

## 9. 实际开奖结果

实际开奖结果独立保存。

| 字段              | 类型      | 说明     |
| --------------- | ------- | ------ |
| actual_result   | object  | 实际开奖资料 |
| actual_zodiac   | string  | 实际生肖   |
| actual_number   | integer | 实际号码   |
| result_verified | boolean | 是否核验   |

### 实际结果原则

实际开奖结果：

* 用于历史验证。
* 用于统计。
* 用于回测。

不得利用实际结果倒向修改该期原始卦象或预测过程。

---

## 10. 分析状态

| 字段                 | 类型      | 说明                                          |
| ------------------ | ------- | ------------------------------------------- |
| analysis_status    | string  | pending / processing / completed / verified |
| verified           | boolean | 数据是否完成核验                                    |
| verification_notes | string  | 核验说明                                        |
| notes              | string  | 其他备注                                        |

---

## 11. 来源追踪

所有重要资料必须保留来源。

建议至少记录：

```text
source
source_file
source_version
import_time
verified
```

目标：

> 任何一个号码或分析结果，都能够追溯到对应的原始资料。

## 13. 数据不可逆原则

以下数据属于基础数据：

```text
RAW
卦象
八肖
生肖号码映射
实际开奖结果
```

这些资料不能因为分析流程而被覆盖。

分析结果属于派生数据：

```text
candidate
28
24
20
16
12
8
```

派生数据可以重新计算，但必须保留规则版本。

---

## 14. 版本控制

当前：

`schema_version: 1.0`

规则或字段发生重大变化时升级版本。

例如：

```text
1.0 → 初始版本
1.1 → 增加字段
2.0 → 结构重大变化
```

所有重大修改必须通过 Git commit 保存。

---

## 15. 香港历史资料特别规则

香港历史资料中已经确定的：

**21画、29画、42画**

必须以实际数据库资料为准。

不能因为资料暂时缺失而使用猜测资料补齐。

特别是历史期数：

> 数据库实际存在什么期数，就记录什么期数。

后续新增资料继续追加，不覆盖旧资料。

## 16. 完整性检查

每一期进入结构化数据库后，应检查：

* [ ] draw_id 唯一
* [ ] 年份正确
* [ ] 期号正确
* [ ] 来源明确
* [ ] RAW 已保存
* [ ] 21画资料（如有）已保存
* [ ] 29画资料（如有）已保存
* [ ] 42画资料（如有）已保存
* [ ] 八肖资料（如有）已保存
* [ ] 号码映射版本明确
* [ ] 候选号码可追溯
* [ ] 28码可追溯
* [ ] 24码可追溯
* [ ] 20码可追溯
* [ ] 16码可追溯
* [ ] 12码可追溯
* [ ] 8码可追溯
* [ ] 实际结果已独立保存
* [ ] 数据完成核验
